1. 设计原则

完整保留 v2 的视觉体系：白底卡片、#2563eb 强调、绿色状态点、英文界面文案、420×540 窗口。v3 只做一件事——把「单向出声音」升级为「双向音频」，模式切换放在 Tab 之上，暗示它是全局状态而非某个 Tab 的内容。

2. 交互模型

  • 模式默认为 Speaker，行为与 v2 完全一致（自动启动 WebSocket、loopback 采集），老用户无感。
  • 切到 Microphone 模式时：停止 loopback 播放流（可选，Settings 里有开关），打开虚拟麦克风推流；Connection 页实时显示电平、来源手机、延迟/码率/丢包三个统计。
  • 两种模式同一时刻只运行一种（互斥），避免 48kHz 双流互相挤占与回声啸叫；这一点也解释 Settings 中 "Pause speaker while live" 开关的存在。

3. 待确认的技术前提（影响 UI 呈现，需要你拍板）

Windows 没有内置的"软件虚拟麦克风"API，要让 Teams/Zoom 看到 "Audio Server Mic"，需要一个输入侧虚拟音频驱动。候选方案：
  • A. VB-Audio Virtual Cable（VB-CABLE） — 现成、免费用于个人用途；UI 文案改为"请在应用中选择 'Cable Output'"。改动最小，但设备名不受我们控制。
  • B. 自研 WASAPI push（用 Windows Audio Endpoint Builder + APO） — 可定制设备名和图标，工作量大且涉及驱动签名，不建议现在做。
  • C. 先不做真注入 — v3 先实现"手机上行 → PC 端接收、电平显示、存 WAV / 本地试听"，驱动注入下一版再接。UI 本稿已兼容此路径（READY 徽章换成 "DRIVER NEEDED" 提示卡即可）。
我的建议：先走 C → A：v3 代码先按 C 实现打通上行链路，UI 上预留 READY 状态；你手工装 VB-Cable 后即可体验完整效果，无需驱动开发。

4. 实现影响（审批通过后）

  • PC 端 main.rs：新增 AppMode 枚举与模式切换行；ServerCommand 增加 SetMode/MicLevel 事件；Settings 页按模式分支渲染。
  • PC 端 server.rs：handle_connection 的 recv 分支目前只打日志，改为解析 mic_start 头并路由上行 PCM 到推流线程。
  • 手机端：新增 mic_mode 页面 + Android AudioRecord MethodChannel（复用现有 com.pcspeaker/audio 插件结构，扩展 startMic/stopMic）。
