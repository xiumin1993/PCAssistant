④ 技术方案（与麦克风模式同构）
数据链路：手机 CameraX 取帧 → JPEG 编码（硬件加速）→ WebSocket 二进制帧 → 电脑 AudioServer 解码（zune-jpeg）→ BGRA32 写入共享内存 → Unity Capture 虚拟摄像头驱动 → 任意应用可见
协议：复用现有 8080 端口。新增 cam_start / cam_stop / cam_request（电脑→手机）文本指令；二进制帧加 0x03 通道头区分麦克风 PCM 与摄像头 JPEG
隐私设计：摄像头不做"自动唤醒"（电脑应用打开摄像头时 Windows 没有可靠的被动感知手段）→ 开启只有两个入口：手机点"开启摄像头"，或电脑点"请求手机开启摄像头"（手机弹红色横幅确认后才会开硬件）。关闭 = 手机随时点红色按钮，或电脑"强制关闭"。守护开关可整体注销
息屏：沿用前台服务；摄像头模式息屏后继续推流（可选"息屏自动停止"省电选项）
需要安装：免费的 Unity Capture 虚拟摄像头驱动（约 2MB，装一次即可，与 VB-CABLE 同类）
⚠️ 待你确认的三件事：
1. 同意安装 Unity Capture 驱动（免费开源，BANDAI NAMCO Studios 出品，会议软件可识别为标准摄像头）；
2. 默认画质 640×480 · 20fps（老机型 Wi-Fi 下最稳），可切 720p·15fps —— 还是想要 1080p？带宽会到 ~15Mbps；
3. 摄像头开启必须手动/电脑请求（不做全自动），因为 Windows 无法像麦克风那样可靠地"被动感知"哪个应用在占摄像头 —— 这是隐私上最稳妥的形态。
